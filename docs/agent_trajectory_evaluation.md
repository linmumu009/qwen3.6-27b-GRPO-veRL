# Agent 轨迹评测文档

## 1. 文档目的

本文说明物流与供应链业务场景下的 Agent 轨迹评估方法，涵盖评估任务、Agent 运行配置、评分标准、数据示例及评测执行方法。

评估对象是模型在业务环境中完成任务的全过程：理解业务问题、读取数据字典、调用工具查询数据、处理工具返回，最终形成可核验的业务回答。评估既关注答案是否正确，也关注执行过程、任务完成情况和工具使用效率。

被评模型为原始 **Qwen3.6-27B** 基座与垂域训练后的 **Step120**。本文的 Step120 指垂域训练版本，不包含后续开源数据续训版本。

## 2. 评估任务与 Agent 配置

### 2.1 评估任务

任务围绕物流业务数据分析展开，由自然语言业务指令、可操作的沙箱环境和评判条件组成。

| 任务形式 | 典型业务问题 | 主要考察能力 |
| --- | --- | --- |
| 数值查询 | 查询指定区域、时间范围内的平均时长或业务指标 | 条件理解、时间口径、聚合计算、单位转换 |
| 结果表生成 | 按业务维度分组，输出指标明细、排序或排名 | 分组与关联、完整行列、排序和结果格式 |
| 多轮业务分析 | 读取业务资料与数据字典，再查询数据库并形成结论 | 信息定位、工具选择、多步执行和结论收尾 |

任务输入与评分信息分开管理。Agent 可以读取业务指令、数据字典、业务资料及任务所需数据库；标准答案、验证 SQL 和判分元信息仅供评分器使用。

### 2.2 Agent 运行方式

评估采用 **PI-Agent 工具协议**，通过接入 veRL 的 `PiAgentLoop` 执行多轮交互。模型负责决定下一步动作，Agent 负责解析工具调用、在独立工作区执行操作，并将工具结果返回模型；模型推理由 vLLM-Ascend 提供。

模型根据业务指令生成工具调用，Agent 执行后将结果返回模型；模型继续查询或形成最终回答，直至任务结束或交互预算耗尽。

PI-Agent 原生会话与 veRL 中的 PI 工具适配共享工具协议，但并非完全相同的运行时。评测需固定执行路径及其版本，避免将不同运行时的结果混在一起。

### 2.3 工具与业务环境

| 工具或环境 | 作用 |
| --- | --- |
| `read` | 读取数据字典、业务说明及执行产物 |
| `bash` | 执行命令、通过 SQLite 查询业务数据 |
| `write` | 在任务工作区保存临时脚本或分析结果 |
| `edit` | 修改任务工作区内的临时文件 |
| `logistics.sqlite` | 提供业务查询的数据环境，按只读要求访问 |
| `schema_dictionary.md` | 说明表结构、字段及业务含义 |
| `documents/` | 提供任务环境中配备的业务规范或说明资料 |

每条轨迹使用独立工作区，避免不同任务之间残留文件或执行状态相互影响。工具调用及其返回结果随轨迹保留，用于后续过程分析和评分复核。

### 2.4 关键运行配置

| 配置项 | 评测设置 |
| --- | --- |
| 模型 | 原始 Qwen3.6-27B 与垂域 Step120 |
| 任务输入 | 冻结业务指令、提示词及任务环境 |
| Agent | PI 工具协议与 `PiAgentLoop` |
| 工具集合 | `bash`、`read`、`write`、`edit` |
| 解码方式 | Greedy，`temperature=0`，关闭随机采样 |
| 总上下文长度 | 49,152 tokens |
| 交互预算 | 最多26个 assistant 回合、25次工具反馈 |
| 评估模式 | 仅推理，不更新模型权重 |
| 评分版本 | 固定原版轨迹解析器与评分器版本 |

评测前检查模型权重身份：基座使用原始权重，Step120 必须完成训练权重到推理服务的同步。权重未同步、工具接口配置错误或评测合同不一致的整次运行，不作为有效评测。有效运行中由模型产生的工具调用错误和未完成任务仍计入统计。

## 3. 评分标准

### 3.1 评分流程

```text
保留完整轨迹 → 解析最终回答和工具记录 → 对齐任务评判条件
            → 计算结果与过程指标 → 汇总评测指标
```

轨迹评分采用原版 `judge_trajectory` 与 `reward_judge`，未启用 LLM judge。评分先识别轨迹是否完成，再分别判断结果、所需表命中和其他过程指标，最后计算综合分。

原版判分与严格复核分别保留评分版本。前者按既有规则生成指标，后者检查答案和执行证据是否足够可靠；两类评分结果不混算。

### 3.2 原版判分条件

以下条件适用于数值与表格查询任务。

| 判定项 | 实际条件 | 解释边界 |
| --- | --- | --- |
| 轨迹完成 | 轨迹按协议结束，解析结果为 `complete=true` | 预算耗尽或未收尾记为未完成，保留在统计中，不因失败而剔除 |
| 合格最终回答 | 轨迹已完成，且最终回答去除空白后不少于20个字符 | 与“最终值正确”是不同条件；仅输出一个短数值可能不通过这一门控 |
| 数值匹配 | 标准数值均能在最终回答提取的数值中找到匹配；每个值满足绝对误差小于 `1e-6`，或非零标准值的相对误差小于 `1e-6` | 原版采用包含式匹配，不要求唯一终值，也不自动证明单位与业务口径正确 |
| SQL结果匹配 | 在同一数据库执行验证 SQL 及轨迹中可提取的 SELECT；任一查询的返回行与标准返回行相等，记为 SQL 匹配 | SQL未匹配时仍可能由数值兜底通过；因此结果通过不等于 SQL 语义已被证明正确 |
| 表格结果 | 原版将 `table` 与 `numeric` 置于同一查询结果及数值匹配分支 | 不能据此宣称已严格核对最终表格的全部行列、重复次数及业务排序 |
| 所需表命中 | 轨迹中识别的表集合包含任务登记的全部所需表；任务未登记所需表时不加这一限制 | 表名命中不能证明连接、过滤、聚合或计算逻辑正确 |

原版结果判定先要求轨迹完成：SQL结果匹配时，若登记了标准数值，还需答案文本包含这些数值；SQL未匹配时，标准数值的包含式匹配仍可使结果判定通过。无可用标准数值且 SQL 也未匹配时，不按正确放行。

**原版联合通过率**要求任务完成、结果判定通过且所需表命中，并不等于完整语义正确率。相关标签定义如下：

| 原版标签 | 判定条件 | 本文名称 |
| --- | --- | --- |
| `correct` | 轨迹完成、结果判定通过、所需表命中 | 原版联合通过 |
| `result_ok_process_mismatch` | 轨迹完成、结果判定通过、所需表未命中 | 结果通过但表未命中 |
| `result_wrong_process_ok` | 轨迹完成、结果判定未通过、所需表命中 | 结果未通过但表命中 |
| `result_wrong_process_mismatch` | 轨迹完成、结果判定未通过、所需表未命中 | 结果与表命中均未通过 |
| `incomplete` / `timeout` | 轨迹未完成 | 未完成 |

这里标签中的 `process_ok` 专指所需表命中，并不表示所有过程质量维度均达标。

### 3.3 原版综合评分

原版综合得分由结果分和过程分组成，取值范围为 **0–1**。

```text
结果分 = 0.5 × 合格最终回答标记 + 0.5 × 结果判定通过标记
过程分 = 表命中、字段命中、资料命中、任务适配的加权得分
综合得分 = 0.5 × 结果分 + 0.5 × 过程分
```

| 过程维度 | 权重 | 原版计算方式 |
| --- | ---: | --- |
| 所需表命中 | 0.30 | 全部所需表是否出现在轨迹识别的表集合中 |
| 字段命中 | 0.30 | 必需字段名在命令文本中出现的比例；不等同于成功执行了正确 SQL |
| 资料命中 | 0.20 | 指定资料标识在命令或回答中出现的比例；不等同于已验证实际阅读 |
| 任务适配 | 0.20 | 数据查询任务中，有可识别 SQL 记1；仅使用 SQLite 探索、没有可识别 SQL 记0.5；均无则记0 |

不适用维度不参与，并对其余权重重新归一。没有合格最终回答时，综合得分直接归零。工具调用、重复命令和其他效率指标保留用于诊断，不加入此版综合分。

综合得分包含过程代理指标，不能直接读作正确率。结果未通过的轨迹仍可能因表、字段等命中获得一定分数，汇总时应分别报告结果判定、联合通过和完成情况。

### 3.4 严格复核标准

严格复核用于排查原版包含式判分和过程代理指标的局限，不与历史原版分数混算。

| 检查对象 | 复核要求 |
| --- | --- |
| 数值终值与单位 | 提取唯一明确的最终值；矛盾候选或多个无法区分的终值不按正确通过。按任务规定单位核对，不能擅自将比例、百分数、分钟与小时混为同值。严格终值复核的默认绝对容差为 `1e-3`、相对容差为 `1e-5`，任务另有登记时以登记值为准 |
| 最终表格 | 核对完整行列和重复行次数；排序、排名或TopN任务按要求核对顺序；无排序要求时按完整行的多重集合比较。不能只匹配某个数值或任意子表 |
| 业务与查询口径 | 核对区域、状态、时间归属、连接条件、分组粒度、聚合方式及单位；表名或字段出现不能替代这些检查 |
| 执行证据 | 工具调用必须对应实际返回；查询需可重放，并核对其返回与最终回答的关系。最终回答中的自报声明不能替代工具证据 |
| 异常归属 | 明确错答、模型工具错误和预算内未完成按失败记录；基础设施或证据缺失导致无法可靠判断时，单列待复核，不伪装成通过或正常负样本 |

**原版联合通过、严格终值通过、执行证据充分是不同结论。** 采用严格规则时，应固定评分版本并统一复评，另行记录结果。

## 4. 数据与轨迹示例

以下为**合成物流业务样例**，用文字展示业务问题、工具调用、工具返回与最终回答。字段、查询和返回值均为演示内容，不是实际模型运行日志，也不作为模型效果证据。

### 4.1 输入与评分信息

| 信息层 | 示例内容 | 可见范围 |
| --- | --- | --- |
| 业务输入 | 业务问题、数据字典、只读数据库及任务工作区 | Agent 可见 |
| 评分信息 | 数值型结果、标准值 `4.25`、单位小时，以及验证 SQL 与所需表字段 | 仅评分器可见，不放入模型提示词 |

### 4.2 文字轨迹示例

**用户提出业务问题**

> 请查询华东区域在2026年9月已签收运单的平均派送时长。按签收日期归属月份，只统计派送与签收时间完整且先后有效的记录，单位为小时，保留两位小数。

**Agent 调用 `read` 读取数据字典**

```json
{"path": "schema_dictionary.md"}
```

**工具返回字段说明**

```text
delivery_records（运单派送记录）
region：区域；status：运单状态
out_for_delivery_at：开始派送时间
delivered_at：签收时间
```

**Agent 调用 `bash` 执行只读查询**

工具参数 `command` 的内容为：

```bash
sqlite3 -readonly -header logistics.sqlite "
SELECT ROUND(AVG((julianday(delivered_at) -
  julianday(out_for_delivery_at)) * 24), 2)
  AS avg_delivery_hours
FROM delivery_records
WHERE region = '华东' AND status = '已签收'
  AND delivered_at >= '2026-09-01'
  AND delivered_at <  '2026-10-01'
  AND out_for_delivery_at IS NOT NULL
  AND delivered_at IS NOT NULL
  AND delivered_at >= out_for_delivery_at;"
```

**工具返回查询结果**

```text
avg_delivery_hours
4.25
```

**Agent 给出最终回答**

> 最终结果：4.25小时。
> 统计范围：华东区域2026年9月已签收运单；按签收月份归属。
> 已排除时间缺失或先后无效的记录。

### 4.3 示例判分

| 检查项 | 演示判定 |
| --- | --- |
| 原版结果判定 | 最终回答包含标准数值，且演示 SQL 返回值一致 |
| 原版联合通过 | 已完成、结果判定通过，且命中所需表 `delivery_records` |
| 严格复核 | 核对唯一终值、小时单位、区域与状态、签收月份和时间有效性；合成 SQL 已执行验证 |

SQL、工具返回和最终回答可以相互核验。仅在回答中声称“已经查过数据库”，不能替代实际工具记录。

## 5. 评测执行与结果管理

评测按以下流程执行：

1. **冻结配置**：确定模型版本、任务定义、沙箱快照、提示词、工具协议、生成预算及评分版本。
2. **核验模型**：确认推理服务加载目标权重；训练模型额外核验权重同步完成。
3. **生成轨迹**：在独立工作区执行多轮工具交互，保留模型动作、工具返回和最终回答。
4. **统一评分**：解析轨迹，计算正确性、完成、过程及效率指标，并保留异常状态。
5. **指标汇总**：汇总结果判定、完成情况、过程指标及异常状态，标注对应的生成配置和评分版本。

| 产物 | 内容 |
| --- | --- |
| 配置快照 | 模型身份、Agent 和工具配置、生成与评分参数 |
| 完整轨迹 | 模型输出、工具调用、工具返回、终止状态 |
| 评分明细 | 结果判定、过程证据、综合分及异常标记 |
| 指标汇总 | 正确性、完成情况、过程指标及平均得分 |

原始任务、完整轨迹、评分明细与指标汇总保留在内部评测归档中。
