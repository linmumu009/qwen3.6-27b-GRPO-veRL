# Step120 物流评测题直接/改写 CPT 对照实验

> 2026-09-05 更正：本文原先对判断题转换的描述与实际代码不符。历史程序生成 `Statement: "原命题" / This statement is false.`，并未把错误命题改写成正确知识。选择题采用 `Question / Correct answer` 文本模板。原有数字保持有效，但“主要是记忆”“停止追加曝光”等机制解释和决策尚缺答案专属损失、原样答案生成及充分拟合诊断支持，应视为暂缓结论。改写自动门禁通过也不等于人工验证了语义等价。

日期：2026-09-04

状态：训练、导出、三次重复评测与配对统计均已完成

用途：受控评测污染诊断，不是有效交付评测

## 结论

本轮提升不能写成交付效果。是否需要继续曝光，须补充答案专属损失、原样答案生成和训练拟合诊断后再决定；此前直接建议停止追加曝光的结论已暂缓。

直接题面 CPT 将 1,672 题的三轮多数票准确率从 Step120 的 `81.878%` 提到 `82.596%`，提升 `0.7177` 个百分点；21 题由错变对、9 题由对变错，净增 12 题，未校正多重比较的 McNemar 精确检验 `p=0.0428`。这是一个小的同题关联信号。

题干改写 CPT 只提到 `82.117%`，提升 `0.2392` 个百分点；10 题由错变对、6 题由对变错，净增 4 题，`p=0.4545`。在严格通过改写校验的 1,625 题上，提升仍只有 `0.2462` 个百分点，`p=0.4545`；47 道恒等回退题对该组增益贡献为零。因此，本轮没有证据支持可靠的语义迁移。

训练本身是成功的：两组 loss 都快速下降，64-step checkpoint 与 HF 导出也完全通过校验。但“模型更会预测这批训练文本”没有转化成等比例的物流问答提升。仅据这次训练，尚不能确定继续曝光的效果，也不能区分答案写入不足与评测格式下调用不足。

## 实验问题与可解释边界

这两组实验回答的是两个不同问题：

1. **直接题面组**：把评测题的正确答案写入 CPT 后，模型对完全相同题面是否变好。它主要测同题关联、答案记忆和格式吸收。
2. **改写题面组**：训练时只看到语义等价的改写题干，评测时仍使用冻结原题，模型是否能把训练信号迁移回来。它比直接组更接近语义迁移，但训练知识点与测试知识点仍然一一对应，所以仍属于污染诊断。

两组都不能回答“模型对未见物流知识是否增强”，也不能替代独立盲测。

## 数据转换合同

冻结输入包含 LogistikaBench 1,446 题和 SC-bench 知识题 226 题，共 1,672 题；源文件 SHA-256 为 `b652b2108cb552346df11d005c15ff3137c50a756a7b24eb35302683ec33ed99`。

直接组采用以下规则：

- 单选题：保留题干和正确选项正文，不写 `A/B/C/D` 等选项字母，不写正确选项索引，不写任何干扰项。
- 多选题：保留题干和全部正确选项正文，共 2,168 段正确答案文本；仍不写索引或干扰项。
- 判断题：历史实现保留原命题并追加 `This statement is true/false.`。这属于真假判断文本，未完成用户要求的错误命题知识化纠正。
- 所有样本都是普通 causal-LM 文本，不套对话模板；按原数据顺序做确定性均衡装箱，每个训练块末尾只增加一个 EOS。

改写组只改题干，正确答案文本、题目身份和评测配对关系保持不变。改写使用本地模型完成，没有把私有题目发送到外部 API。严格门禁检查了空输出、答案/选项泄漏、过高原文重合、明显语义漂移以及否定极性变化。1,625/1,672 题通过门禁，覆盖率 `97.189%`；剩余 47 题因多次改写都未安全通过，显式保留原题干并标记为 `identity_fallback`，没有伪装成成功改写。

| 语料 | 题目数 | 改写题数 | 训练块 | 每遍 content token | 每遍含 EOS token |
|---|---:|---:|---:|---:|---:|
| 直接题面 | 1,672 | 0 | 64 | 93,321 | 93,385 |
| 改写题面 | 1,672 | 1,625 | 64 | 88,441 | 88,505 |

改写文本更短，因此两组控制的是相同题目数、训练块数、step 数和曝光次数，并非精确相同 token 数；改写组每遍 token 比直接组少 `5.23%`。这会轻微影响绝对比较，但不足以把无显著改写收益解释成可靠语义迁移。

## 训练设置与完整性

两组均从相同 Step120 model-only checkpoint 独立启动，各自新建 optimizer，不串行继承对方权重；使用 5 号机原 veRL 训练容器和 16 张 NPU，拓扑为 TP4 × PP2 × CP2。每遍 64 个训练块，全局 batch 4，即每遍 16 optimizer step；连续 4 遍共 64 step。学习率从峰值 `5e-7` 余弦衰减到 `1e-7`，有效 warmup 为 2 step，MTP 关闭并冻结。

## 如何解释 loss 与准确率的背离

两组第一遍到第四遍的 loss 大幅下降，说明优化器确实学会了更好地预测训练文本。它不等价于学会回答题目，原因包括：

- CPT 的目标是下一个 token，而正式评测要求稳定选择答案；两者的输出协议不同。
- 单题文本很短，连续四遍更容易强化局部表述和答案共现，而不是形成跨表达方式可调用的知识。
- Step120 基线已经达到 81.878%，剩余错误包含歧义题、长选项池、标签噪声和模型推理/解析失败，并非都能靠注入答案文本修复。
- 直接组效果大于改写组，且改写组相对基线不显著，更符合“同题面关联较强、跨表述迁移较弱”的解释。
- `p=0.0428` 是未做多重比较校正的单次配对检验，效应只有 12 题；它适合作为机制信号，不足以证明产品收益。

## 决策与下一步

1. **先补答案吸收诊断再决定是否追加曝光。** 全文本 loss 缓慢下降不足以证明答案充分拟合；应先检查答案概率和训练前缀下的答案生成，再决定训练强度与监督方式。
2. **两组 checkpoint 均不得晋级或用于交付分数。** 测试题及其语义等价变体已经进入训练，哪怕评测仍用原题，结果也已经失去独立性。
3. **另建来源和概念双隔离的数据。** 从已获授权书籍、物流标准、百科/公开机构资料中提取物流概念；先按来源、章节和概念簇去重，再把完整概念簇划入 train 或 blind test，不能把同一事实的改写分别放到两边。
4. **若交付目标是知识问答，优先做答案生成式 SFT 金丝雀。** 训练样本使用自然问题、解释性答案和必要依据，而不是只有题干与答案拼接；混入通用指令回放和既有物流 Agent 轨迹，控制遗忘。CPT 可作为多来源语料的低学习率前置阶段，但不应继续围绕评测题本身。
5. **保留双重门禁。** SC-bench/LogistikaBench 只作为“已污染诊断集”观察模型行为，不再当作晋级主指标；真正晋级依据应是从未参与训练、改写提示或调参的盲测集，同时继续检查原 Agent 与通用开源能力不回退。
