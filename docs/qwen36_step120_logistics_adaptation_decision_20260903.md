# Qwen3.6-27B Step120 物流知识适配调查与决策

日期：2026-09-03

## 决策

**当前不启动《The Handbook of Logistics and Distribution Management》第八版的继续预训练。**

推荐路线不是“单书纯 CPT”，而是：

1. 先冻结并实测 Qwen3.6-27B 原生模型与当前 Step120 的逐题基线；
2. 仅使用权利清晰、与评测隔离的多来源物流语料，构造“领域语言建模 + 阅读理解式知识利用 + 原能力回放”的小型混合适配；
3. 再用物流问答、原 Agent 轨迹和原开源任务做短程对齐恢复 SFT；
4. 只在物流知识提升、Agent/开源能力不退化、逐字记忆受控三类门禁同时通过后晋级。

如果暂时只有这一本书，则不做 CPT。短期交付优先采用检索增强；如已取得该书训练授权，可从书中生成少量有出处、经人工核验、与评测去重的阅读理解/问答样本，做 SFT 小试，但不能据此宣称已经完成物流领域预训练。

### 为什么一本书不够

清理后可用正文约 37.0 万 token。按 8,192 token 打包只有约 45 个满序列；即使全参训练能够运行，一个 epoch 也只有极少的优化批次。增加 epoch 会把“数据不足”变成“重复记忆”，而不会补齐运输、仓储、物料搬运、采购、供应链计划、履约协同、海关与法规等不同来源和表述分布。

因此，这本书可作为已授权语料池中的一个高质量骨架来源，但不能作为 27B 模型 CPT 的唯一语料。工程上建议先建设 **20M–50M 去重后的独特物流 token**，至少来自 5 类互相独立的来源；先用 5M token 做金丝雀，再决定是否扩量。这是本项目的试验预算，不是通用缩放定律。

## 权利门禁

版权页明确存在“未经出版社事先书面许可，不得用于 AI/机器学习训练”的限制，而文件中没有附带训练授权证明。

因此当前状态为：`blocked_pending_rights_confirmation`。需要由数据权利负责人确认下列任一证据后，才可把正文发往模型接口、制成训练样本或放入训练集：

- Kogan Page 或相应权利人的书面训练许可；或
- 已签订的企业许可明确覆盖模型训练、派生样本和内部模型交付。

购买电子书、持有 TXT 或内部共享文件本身不能替代这项确认。本报告只记录工程与数据治理事实，不构成法律意见。

## 与评测集的重合

### 本地实测规模

- LogistikaBench：1,446 题。
- SC-bench 知识题：226 题，分别为 63 道多选、82 道单选、81 道判断；另有 100 道工具题，不计入本轮知识题文本重合。

### 逐字重合结果

| 评测集 | 完整题干重合 | 任意 8 词连续重合 | 12/16/24 词连续重合 |
|---|---:|---:|---:|
| LogistikaBench | 0/1,446 | 0/1,446 | 0 |
| SC-bench 知识题 | 0/226 | 0/226 | 0 |

LogistikaBench 列出的五个原始来源标题也都未在书中发现。当前没有“书中直接包含评测题”的证据。这个结论只排除了逐字泄漏，不能排除概念层面的覆盖；概念覆盖正是领域训练希望获得的能力。

若后续从书或其他语料生成 QA，仍必须重新对题干、选项、答案解释做 8/12/16/24-gram 去重，并按来源文档切分 train/dev/held-out，不能把同一章节随机切片后分到不同集合。

## Step120 是否适合继续训练

**适合做新阶段的初始化权重，但不适合按原优化器状态“无缝续跑”。**

5 号机上的实际模型为：

```text
/data3/llin/qwen3.6-27b-verl-grpo/runs/
llin-step120-opensource-20260825-02/
```

只读核验结果：

- 20 个开源数据更新已经完成，global step 为 120；
- Megatron model-only checkpoint 有 32 个分片，共 54,720,369,973 bytes，结构与 Step100 一致；
- HF 导出有 15/15 个 safetensors 分片、1,199/1,199 个 tensor，缺失、额外和 shape mismatch 均为 0；
- 原 run 在保存 optimizer 时因磁盘空间不足失败，后续恢复为有效的 model-only checkpoint；
- optimizer state 与 RNG state 不存在，任何后续训练必须新建 Adam、学习率日程和数据游标。

这不妨碍新的 CPT/SFT 阶段，因为目标函数和数据已经改变，本来就不应继承 GRPO 的优化器动量；报告中应使用“从 Step120 权重初始化”，而不是“精确恢复 Step120 训练状态”。

## 5 号机可执行性

- 16 张 NPU 均健康且空闲。
- `/data` 可用约 413GB；`/data3` 可用约 139GB、已使用 97%。
- 现有 veRL SFT 链路已经在 16 张 NPU、TP4/PP2/CP2、全新 Adam 下完成过真实前反向和更新。
- 当前训练容器只找到 veRL SFT trainer，没有找到 `pretrain_gpt.py` 一类真正的自回归 CPT 入口。

所以不能把“把整本书装进一个 assistant 消息再跑 SFT”冒充 CPT。正式试验前需要新增并验证 packed causal-LM 数据集与训练入口；先做 1 step 不保存模型的前反向门禁，再做 5M token 金丝雀。输出不能继续写到接近满盘的 `/data3`：模型加完整 Adam 预计会再次超过空间余量，应把新 run 放到 `/data` 的独立目录，或只为不续跑的金丝雀保存 model-only 结果。

## 推荐数据方案

### 有书籍训练授权

建立至少 20M–50M 独特 token 的物流语料池：

- 书籍清洗正文：约 0.37M token，最多曝光 1–2 次；
- Wikipedia 物流概念图谱：从物流、供应链、仓储、物料搬运、运输方式、库存、采购、履约、海关等根概念，按 Wikidata/分类扩展并保留页面 URL、版本和授权信息；
- 权利明确的政府/国际组织材料：例如 World Bank 的 *Trade and Transport Corridor Management Toolkit*，逐文档保存许可证并剔除第三方图表；
- 企业已有、已授权且脱敏的物流 SOP、术语、异常处理和业务文档；
- 一般能力回放语料：使用原 Agent 轨迹和已获准的开源训练数据，不从评测集反向制数。

Wikipedia 适合补“概念广度”，但不够补“业务深度”：其文本可通过 Hugging Face 的 `wikimedia/wikipedia` 或 Wikimedia dump 获取，必须保留页面级 attribution 和相应 CC BY-SA/GFDL 义务。FineWeb-Edu 可作为一般语言回放候选，不应直接按物流关键词抓取后默认拥有所有上游网页的训练权；数据集卡本身也提示受 Common Crawl 条款约束。

### 没有书籍训练授权

完全排除该 TXT，采用 Wikipedia、World Bank/政府开放材料、企业自有文档和一般能力回放。若交付时间很短，先做 RAG：它能立即改善知识问答，同时避免把整本受限书籍固化进权重。模型内化训练等开放语料达到规模、去重和许可门禁后再做。

## 推荐训练设计

### Stage 0：先测，不训练

1. 冻结 LogistikaBench、SC-bench 知识题、SC-bench 工具题、原 Agent 密封集和开源密封集哈希。
2. 对原生 Qwen3.6-27B 与 Step120 做同题逐项比较，报告 0→1、1→0 转移和类别宏平均，而不只看总分。
3. 若书籍授权成立，在 5 号机本地对原生模型做 32/64/128 token 前缀、每档至少 200 个按章节分层且互不重叠的续写检测，并配合原文/扰动盲选；不用百炼上传受限正文。
4. 另建 300–500 道不复用评测来源、按来源文档隔离的隐藏物流知识题，防止围绕两个公开 benchmark 调参。

### Stage 1：5M-token 混合知识适配金丝雀

建议数据配比：

- 50% 清洗后的多来源物流自然文本；
- 20% 由同一物流文本转成的阅读理解式知识利用样本；
- 30% 一般语言/原能力回放。

从 Step120 model-only 权重初始化全新 Adam。首轮只比较 `5e-8` 与 `1e-7` 两个低学习率臂，短 warm-up 后衰减；每个来源文档最多曝光两次。具体 batch 和步数按真实 packed token 数反推，不用“20 步”代替 token 预算。

### Stage 2：对齐恢复 SFT

通过 Stage 1 后，做一次短 SFT：50% 物流 QA/解释/情境题、25% 原 Agent 轨迹、25% 原开源指令数据。物流回答只使用有出处且经机械/人工双重核验的答案；评测题、同源改写题和列出的 benchmark 来源全部隔离。

### 备选臂

若 Stage 0 显示原模型“知道概念但不会按题型回答”，跳过 CPT，直接比较 SFT-only 与 RAG；若知识题和闭卷解释都显著缺失，才保留混合知识适配臂。这样可以区分“知识缺口”和“知识调用/格式缺口”。

## 晋级门槛

在训练前登记以下门槛，并使用配对 bootstrap 95% 置信区间：

- LogistikaBench 和 SC-bench 知识题类别宏平均至少各提升 3 个百分点，或其中一个提升至少 5 点且另一个不下降；
- 原 Agent 密封集、原开源密封集和 SC-bench 工具题均不下降超过 1 个百分点；
- 逐题 1→0 遗忘数量不被总平均掩盖；
- 领域隐藏集同步提升，排除只拟合公开 benchmark；
- 训练语料对所有评测的完整题干和 8+ 连续词重合为 0；
- 长续写逐字命中相对基线不得异常上升，且不得用重复曝光换分；
- checkpoint 必须通过分片、tensor、shape、哈希和独立加载门禁。

## 研究依据

- Gururangan 等人的领域/任务自适应预训练工作证明多阶段领域预训练可以改善下游任务，但研究使用的是领域语料集合，不是单本书：[ACL 2020](https://aclanthology.org/2020.acl-main.740/)。
- AdaptLLM 发现原始领域文本 CPT 能注入知识，却可能显著损害问答提示能力；把文本转成阅读理解任务更利于知识使用：[ICLR 2024](https://arxiv.org/abs/2309.09530)。
- Mix-CPT 把知识学习和格式对齐解耦，并用混合知识任务和自蒸馏降低遗忘：[ICLR 2025](https://arxiv.org/abs/2407.10804)。
- Ibrahim 等人显示学习率重新升温/衰减配合旧数据 replay，能明显缓解连续预训练的分布迁移与遗忘问题：[TMLR 2024](https://arxiv.org/abs/2403.08763)。
- ICLR 2026 的大规模逐样本研究提示，领域 CPT 会出现中等程度遗忘，平均分会掩盖 1→0 与 0→1 的不同转移，支持本项目采用逐题配对门禁：[ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/bc1c5e5fb8ed1ef9b9b5abced2022e40-Abstract-Conference.html)。
- Wikipedia 的 Hugging Face 数据卡说明其来自官方 dump，并列明 CC BY-SA/GFDL 及页面字段；使用时仍需履行许可义务：[wikimedia/wikipedia](https://huggingface.co/datasets/wikimedia/wikipedia)。
- World Bank 的走廊管理工具包明确以 CC BY 3.0 IGO 提供，可复制、传播和改编，但第三方组件需另行核验：[World Bank Toolkit](https://documents1.worldbank.org/curated/en/719971468325781473/pdf/Trade-and-transport-corridor-management-toolkit.pdf)。
