# 原生模型与 Step 120 的独立 64 题短协议审计

日期：2026-08-12

## 结论先行

同一批与冻结 16 题、val20、test20 均不重叠且经当前任务定义机械核验的 64 题，在最多 3 个助手回合下：

- 原生 Qwen3.6-27B 只有 `1/64` 题发出可识别的只读 SQLite 查询；
- 真实 Step 120 有 `4/64` 题发出可识别查询，略优于原生，但仍远不足以构造训练数据；
- 两者都把绝大部分早期工具预算用于 `ls/find/grep/read/head` 等环境和模式探索，并且恰好各出现 `83` 次重复 Bash 命令；
- Step 120 仅形成 `1` 个“实际错误 SQL + 真实工具结果 + 机械正确 SQL”训练 pair，低于预注册的 `48` 对门槛，所以没有启动 optimizer，也没有产生 checkpoint。

因此，“短预算内持续探索、不尽快查询数据库”的模式在原生模型中已经存在，不是 Step 120 训练新制造的类似奖励黑客行为。Step 120 的早期 SQL 进度从 `1/64` 提高到 `4/64`，现有证据也不支持训练放大了这个模式。更准确的解释是：原生工具策略缺陷与 3 回合协议过短共同造成数据门禁失败。

## 权重身份与证据边界

最初标作 Step 120 的短运行日志明确显示跳过 actor 到 vLLM 的初始权重同步。该运行实际由原生 Qwen3.6-27B rollout 权重生成，不能作为 Step 120 证据；本报告只将其作为同输入、同解码的原生取证对照。

修复后运行通过序列化 trainer 配置强制执行 checkpoint 同步，并在同步完成后进入 rollout；它才是本报告的 Step 120 侧。后续启动器还新增了显式 force/skip 日志门禁，缺少 force 标记或出现 skip 标记都会把整次运行判无效。

该 64 题实验只观察前三个助手回合，不包含完整任务完成与老板奖励评分，不能替代完整 25 工具回合的自然行为归因。16 题相同错误状态下的 teacher-forced margin 对照不经过 vLLM 权重同步路径，仍然有效。

## 聚合结果

| 指标 | 原生模型 | Step 120 |
| --- | ---: | ---: |
| 任务数 | 64 | 64 |
| 工具调用 | 252 | 377 |
| Bash 调用 | 213 | 283 |
| read 调用 | 39 | 94 |
| 进入可识别只读 SQLite 的任务 | 1 | 4 |
| 可识别只读 SQLite 调用 | 1 | 7 |
| 未解析或非只读 SQLite 调用 | 6 | 12 |
| 重复 Bash 调用 | 83 | 83 |
| 有未观测工具调用的任务 | 64 | 59 |

Step 120 的首错 pair 构造结果为：`60` 题没有只读 SQL，`3` 题首个只读 SQL 没有真实工具返回，仅 `1` 题形成可用错误 pair。构造器没有合成工具结果，也没有把无 SQL 轨迹伪造成负例。

## 决策

训练门保持关闭。下一步不是降低 48 对门槛，也不是用环境探索命令充当 rejected，而是在完全相同的 64 个独立任务上延长交互预算，获得真实执行并观测到的首个 SQL。延长运行仍固定 Step 120、greedy `n=1`、48K、老板四工具与同一输入；只有重新形成至少 48 对，才允许执行 forward-only margin 门禁。

无论延长结果如何，当前短协议都不授权训练或 checkpoint 晋级。
