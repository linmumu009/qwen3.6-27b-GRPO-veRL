# SC-bench / LogistikaBench 同题得分专项优化

## 目标与范围

用户明确将目标限定为提高这两个数据集上的实际得分，不要求本轮测试泛化。实验直接使用已冻结的1,672道评测题及金答案训练；输出必须标注为训练过评测题后的同题成绩，不作为独立测试或通用能力证明。

这不是上一轮知识陈述制数，也不是继续重复书籍CPT。训练保留原题目、全部选项和原顺序，复用正式评测的系统提示、用户提示及关闭thinking的chat模板；监督输出是零基索引的答案JSON，多选题使用完整正确答案集合。

## 执行顺序

1. 冻结源文件哈希，逐条验证1,672条训练记录。使用与正式评测完全相同的prompt token IDs，单独追加金答案JSON token和EOS，避免拼接后的重新分词改变推理前缀；只监督答案与EOS。
2. 补测之前两个八题模型：各跑完整1,672题、温度0、同seed1024、TP8单副本、并发64、4,096上下文、输出上限96 token。每个模型重复3轮，报告单轮结果及逐题严格多数票，沿用历史Step120同协议多数票基线。
3. 全量答案监督训练从Step120模型态独立初始化fresh Adam，训练2遍；全局batch 4，每遍418步，共836步，在第418/836步保留模型检查点。两遍之间不中断、不重置优化器。
4. 完整性校验后依次导出并正式评测两个检查点，使用与八题模型相同的评测设置。只比较这两个原数据集，不另加改写题或新场景。

每题金JSON都通过现有评分解析器的roundtrip核验。完整输入、答案和EOS均参与前向，只有金JSON及EOS计入损失。训练集验证仍是同题，不能称为独立验证。

## 训练配置与资源边界

- 复用5号机原veRL/Megatron容器，TP4 × PP2 × CP2、16 NPU，全参数文本训练；视觉/MTP沿用原路径的冻结设置，显式关闭MTP训练。
- 学习率和最低学习率均为2e-6，warmup比例1%，Adam beta显式0.9/0.999，梯度裁剪1.0，weight decay 0。优化器驻留设备侧。
- 只保存两个model+extra检查点，不保存优化器，不能从这些检查点精确恢复中断后的优化器轨迹；这是磁盘预算选择，不影响不中断时1遍到2遍的连续训练。
- 原容器没有挂载空闲的/data1，本轮不改容器挂载，也不删除历史产物。开始训练前至少需要260GB空闲，单次HF导出前至少需要95GB空闲；预算包含两个模型检查点、两个HF导出和预留空间。
- 运行目录禁止覆盖，整条流水线持有物流训练独占锁；任一步失败停止并写入状态，不静默跳过失败样本。

## 评分和模型选择

主表分别列出两个数据集的题数、答对数、准确率和解析失败数，同时列总分；多选采用正确索引集合完全匹配。三轮按解析答案做逐题严格多数票，三种答案各一票视为没有多数，不挑选最高单轮成绩。

候选只在两个数据集答对数均不低于Step120时进入推荐集合，再按总答对数选最高者；平分保留较早候选或基线。该规则避免总体分数遮盖某一数据集下降，不是独立测试晋级门槛。用户尚未给出“足够好”的数值目标，因此只报告实测最高得分，不擅自宣称已达成最终要求。

另列原八题在正式选择题格式下的答对数，以区别此前的8/8金答案原样续写。金答案续写命中不等于正式题面得分。
