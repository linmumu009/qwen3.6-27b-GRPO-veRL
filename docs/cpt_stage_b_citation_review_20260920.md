# 阶段 B 引用修复与内容核验

日期：2026-09-20。范围：固定 run04 的32道原始候选，不重新制题、不改变原判。本轮新增模型调用0次。

## 结论

引用接口确实过严，但不是唯一问题。支持多个可定位原文片段后，26/32题的引用均可找到；保留其他原检查时，12题进入本地内容审阅，仍没有完整四题组。这12题中4题有实质语义疑点、2题有设计问题，6题的答案集合暂获来源支持，但仍未通过完整设计和隔离检查。**0组放行，当前不值得继续用旧盲审提示补跑模型。**

本地审阅者已见作者答案，并非独立盲审；这是排错证据，不能当作独立正确率。来源支持的判断不等于最终合格。

## 引用核验方式

仅规范化空白与换行，按显式省略号分段，每一段保持字词、大小写和标点不变，在来源中精确定位。保存全部匹配位置、原始字符偏移及对应原文，不把不连续摘录伪装成一个连续引文，不用模糊相似度放行。短片段单独标记，定位成功不代表证据充分。

未完全定位的6题包括：MIT两题跨项目符号直接拼接；GVC两题涉及未显式标记的跨段拼接、PDF抽取控制字符与连字符差异；铁路两题包含未标明的跨章节拼接。这里没有把这些差异自动归为事实错误，也没有静默改原文。

原来源包和任务正文均未修改。每题保存独立内容指纹，原始调用文件及来源包指纹也保留。

## 格式检查仍需修复的部分

除引用检查外，按原校验顺序首次报告：9题缺少规定的明确多选指令、4题长度/设计、2题位置依赖、1题选项数量。这些不是穷尽的多标签问题计数，也不与引用失败数简单相加。

- 位置依赖检测没有词尾边界，误把 `option because` 中的 `option b` 视为索引引用；该题还有一个55词选项，修正误报也不满足原50词限制。
- 另一题的 Option A/B 是题干内固定运输方案名称，并非展示顺序的选项索引；应做语义检查，不能仅靠字母匹配判不允许换位。
- 明确多选提示缺失应与语义错误分开；有些题虽使用复数询问，仍未满足预先约定的清晰指令。不能未经版本登记直接改题。

上述问题保留在原判中；本审计没有追溯宣称首批通过。

## 12题逐选项内容审阅

| 处置 | 题数 | 主要发现 |
|---|---:|---|
| 语义疑点，暂缓 | 4 | 企业与东道国收益主体混淆；2道拣选题作了来源不支持的比较推论；铁路速度分类缺少专用线路设计前提 |
| 设计问题，暂缓 | 2 | 反例题实际上要求区分非独有特征；应用题添加无计算作用的任意数字 |
| 答案集合有依据，设计/隔离待查 | 6 | 交通模型1、运输方式1、低水位3、港口预测1；不能直接视为合格题 |

关键反证来自原盲审已通过的 `picking_workload-competing_rules`：来源只说小件拣选更费时，不能推出把小件移到另一区“无效/不允许”。同一道题的作者和盲审都接受了这个过强结论，说明同模型分上下文审阅仍可能共享推理错误。

另一道拣选题把总体55%旅行占比推为托盘拣选的旅行占比更低，并进一步给出小件优先布局结论；来源没有提供分类型占比、频率或数量。这不只是引文字符串问题。

铁路应用题中，用250 km/h断言“专用高速车辆”的理由缺少专用线路设计条件；固定编组也不能决定速度类别。GVC题把东道国价值获取困难写成企业部门收益困难，同样需要区分主体。

低水位三题虽答案集合可由教材支持，但情境和机制高度相邻，不能直接当作三项独立迁移证据。反例形式及题面重叠仍需审查。

## 已实现的新引用表示

已为8组来源建立带稳定ID的段落目录，保存原文、字符起止位置和指纹。后续模型只引用这些ID，避免自行重写长引文。

逐选项审阅结构为：

```json
{
  "option_index": 0,
  "relation": "entailed",
  "source_ids": ["group:p000"],
  "reason": "解释来源与该选项之间的推导关系"
}
```

relation仅允许 `entailed`（可推出）、`contradicted`（被反驳）、`insufficient`（依据不足）。每个选项必须出现一次；前两类必须引用存在的来源ID。不能把“依据不足”自动当成错误选项。结构校验只验证完整性与引用存在，不证明逻辑成立。

新增程序没有改变正式评测解析器、原制题规则或原候选标签，也没有自动执行新盲审。原文目录保持私有。
