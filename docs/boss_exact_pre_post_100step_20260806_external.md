# 原版评分器评测：冻结模型 vs Step 100

日期：2026-08-06

评测集：固定同源评测集

## Executive Summary（结论摘要）

- **Step 100 的原版总奖励没有提升，均值下降 7.37%。**
- **数值正确性和过程质量出现小幅正向信号，但未能转化为总奖励提升。** 主要原因是未完整收尾的比例上升，触发硬门控归零。
- **下一轮应优先优化最终回答预算和重复探索。** 先恢复完成率，再判断过程能力提升能否稳定转化为总奖励提升。

## 评测口径

本次未使用项目内的评分复刻值。冻结模型和 Step 100 的既有贪心轨迹均转换为原版评分器要求的消息格式，并直接调用原始评分流程。

两轮评测使用同一任务清单和同一评分版本，按任务标识精确配对。未启用 LLM judge：评测任务均为 numeric/table DWH，原版流程默认也关闭 LLM judge。

当前评分规则为：

1. `has_answer=0` 时总奖励直接为 0。
2. `result_score = 0.5 × has_answer + 0.5 × answer_ok`。
3. `process_score` 对 tables、fields、docs、task fit 按 `0.3/0.3/0.2/0.2` 加权，`None` 维度跳过并重新归一。
4. `reward_total = 0.5 × result_score + 0.5 × process_score`；效率指标只记录，不进入总奖励。

## 主要结果

| 原版指标 | 冻结模型 | Step 100 | 变化 |
| --- | ---: | ---: | ---: |
| `reward_total` 均值 | 0.479065 | 0.443750 | **-0.035315（-7.37%）** |
| `result_score` 均值 | 0.425000 | 0.400000 | -0.025000 |
| `process_score` 均值 | 0.670625 | 0.765000 | **+0.094375** |
| 完整收尾率 | 75% | 65% | **-10 个百分点** |
| 合格最终回答率 | 75% | 65% | **-10 个百分点** |
| 数值结果正确率 | 10% | 15% | **+5 个百分点** |
| 原版 verdict=`correct` 占比 | 5% | 10% | **+5 个百分点** |
| 必需表命中率 | 60% | 75% | **+15 个百分点** |
| 必需字段命中均值 | 0.558824 | 0.647059 | +0.088235 |
| task fit 均值 | 0.875000 | 0.900000 | +0.025000 |

逐题配对总奖励表现为：30% 提升、25% 下降、45% 持平。正确性有新增也有丢失，净变化为正；但当前评测规模有限，尚不足以证明稳定的泛化提升。

## 为什么过程变好、总分反而下降

Step 100 更积极地查表和展开答案：

| 行为指标 | 冻结模型 | Step 100 | 变化 |
| --- | ---: | ---: | ---: |
| 平均 SQL 数 | 9.25 | 11.70 | +2.45 |
| 平均命令数 | 25.95 | 28.30 | +2.35 |
| 平均重复命令数 | 18.80 | 21.55 | +2.75 |
| 平均答案长度 | 1,507.45 | 4,349.25 | +2,841.80 |

在两轮均完整收尾的共同题目上，原版总奖励从 `0.61188` 提升到 `0.70938`，增加 `0.09750`（+15.93%）。这说明训练后的已完成轨迹在过程命中和部分结果能力上确有改善。

但配对转移显示，“完成 → 未完成”的案例多于“未完成 → 完成”的案例，其中还包含原本正确、训练后未完整收尾的退化。由于原版评分器对未完整收尾执行硬门控、总奖励直接归零，过程分的提升不足以抵消完成率下降。

## 判断与建议

若问题是“训练 100 步后，在原版评分器上有没有提升”，答案应分成两层：

- **总奖励：没有，反而下降 7.37%。**
- **已完成轨迹的任务过程和数值正确性：有小幅正向信号。** 过程分提高 `0.0944`，数值正确率、必需表命中率和任务匹配度均有所提升；但更长、更重复的工具探索让完成率下降，最终压过这些收益。

因此下一轮不应原样继续增加训练步数。更直接的改动是把 `has_answer` 硬门控和“预留最终回答预算”纳入训练与 rollout：在接近工具轮次或 token 上限前强制进入最终回答，减少重复 SQL，并继续使用同一套固定评测口径做短程 A/B。先修复完成率，再判断过程能力提升能否转化为总奖励提升。
