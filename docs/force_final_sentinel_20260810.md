# Step 120 强制收尾快速门禁

## 结论

当前不应把正式训练直接扩到 64K/96K，也不应立即续训 100 步。48K 下的强制收尾已经证明：提前停止继续调用工具可以显著提高完整收尾率，但尚未提高最终数值正确性。当前瓶颈从“没有最终回答”进一步收敛为“查证链和最终综合仍会得出错误结果”。

推荐下一步先做预算感知的工具调用拦截和少量纠正监督；在同一运行、同一任务、同一随机设置下完成 control/treatment 配对门禁后，再决定是否进行 5 步训练。96K 只保留给确有证据表明“正确证据已经取得、只因上下文截断而丢失”的定向诊断。

## 实验设计

- 冻结模型：Step 120 Megatron distributed checkpoint；本轮没有更新模型参数。
- 上下文：`49,152` tokens，保持现有 48K 配置。
- 收尾策略：达到助手回合阈值或只剩保留 token 预算后，禁用工具并要求立即给出最终回答。
- 最终回答上限：`4,096` tokens；若模型仍发起工具调用，拒绝该调用并最多纠正重试一次。
- 评分：先记录在线奖励，再把轨迹无损适配后直接调用老板原版 `reward_judge.py`。
- sentinel6：4 道 Step 120 未收尾题 `000070/000080/000133/000196`，以及 2 道原本已收尾的完成率护栏题 `000048/000269`。

## 决策

1. 暂不做 64K/96K 全量训练。更长上下文会增加 KV cache、降低并发并放大长尾，但现有证据没有显示正确答案只是被上下文边界截掉。
2. 暂不把当前强制收尾策略直接用于训练。它可以改善完成率，却可能把尚未校验充分的中间结果固化成错误答案。
3. 下一版优先实现“预算感知的下一次工具调用拦截”：在允许新工具调用前估算剩余上下文能否容纳工具返回和最终回答，而不是只按固定回合数触发。
4. 从本轮错误轨迹提取少量纠正样本，监督模型完成“关键字段/时间范围/聚合粒度核对 → 数值复算 → 简洁最终回答”；先用离线 SFT/DPO 或重排门禁验证，不立刻扩展到 100 步 GRPO。
5. 进入训练前的质量门槛：同一运行内至少救回 2/4 未收尾题、6/6 都有最终回答、护栏题不回退，并且至少出现可复现的最终数值正确性提升。未满足时继续停在便宜的冻结模型评测阶段。
