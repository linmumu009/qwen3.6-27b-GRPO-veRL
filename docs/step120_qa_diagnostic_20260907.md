# Step120：知识储备与问答应用的初步诊断

## 目标与状态

用户最新目标是提升供应链领域实际问答能力，SC-bench/LogistikaBench作为衡量工具；不再把在评测题上训练后的高分当作能力证明。本轮只做推理诊断，不做CPT或SFT，也不使用任何接受过评测题CPT/SFT的候选。唯一模型为原训练起点Step120。

2026-09-07已完成5号机推理流水线，并从逐次预测重新核算全部多数票、探针门禁和安全汇总。结果见[无正文汇总](step120_qa_diagnostic_results_20260907.safe.json)。注意：363题中259题的自动审核结果为缺失或无效，不能把它们归为资料不足；后续八题复核与补证见[复核记录](step120_evidence_review_20260907.md)。

错题来自原始1,672题三轮多数票的固定303题，不随本轮重新作答而重新筛选。冻结源文件和基线哈希，核对题面、选项、金标签及历史评分一致性。对照以按数据集/类别/题型排序的错题作系统抽样锚点，选未重复使用的最近原答对题；优先匹配数据集、题型、类别，再匹配选项数与题干长度。此次60题全部实现数据集、题型和类别精确匹配，但不是随机总体代表样本。

## 四个条件

| 条件 | 输入 | 用途 |
|---|---|---|
| 原题闭卷 | 原题与选项 | 当前诊断条件下的对照，不沿用历史错题必错的假设 |
| 原题＋教材 | 原题与选项，加独立书籍片段 | 观察补充资料后的答对/答错变化 |
| 基础知识题闭卷 | 与原题相关的定义或基础事实选择题 | 检查更简单的知识调用 |
| 基础知识题＋教材 | 同一基础题，加相同书籍片段 | 检查有资料时能否回答基础题 |

四个条件都使用同一中性系统指令，不暴露“原错题/原答对题”标签。由于诊断指令和上下文上限与历史正式评测有差别，本轮闭卷结果只作配对对照，不替换原正式成绩。有效基础题只在自动检查通过的子集测试，不能将该子集分母当作363。

每个条件3轮、温度0、seed1024、TP8、最大并发64、8,192上下文，正式作答输出上限96 token。轮间反转条件运行顺序；逐题按解析答案的严格多数票计分，并报告不稳定和无多数的数量。提供金答案索引集合仅用于本地评分，不进入模型作答输入。三个不同答案各一票不取其中最佳者。

## 独立资料与自动探针的边界

资料仅来自用户之前提供并授权的《The Handbook of Logistics and Distribution Management》第八版的既有私有书籍Parquet，不使用从评测题和金答案生成的知识候选。按Step120 tokenizer生成1,183个最长384-token窗口，记录原书块索引、token偏移和片段哈希；检索使用题干及全部未标注选项，BM25式评分对题干词权重3、选项词权重1，每题取最多3个不过度重叠片段。检索输入不包含金标签。

所有363题均有词法检索命中，但命中不代表内容相关或充分；教材可能不覆盖部分主题、司法辖区和细节。单书覆盖不足必须保留为未解决问题，不能解释成模型缺乏推理能力。

探针作者和审核器也使用Step120的独立无状态请求，因此不是独立专家。作者只看原问题、未标注选项和书籍片段，不看金标签、历史预测、分组身份。基础题要求4个唯一选项、唯一答案、原文中的逐字支持引文，并自动检查是否为相关基础事实、是否只是原题重述、答案是否唯一及有依据。选项按固定hash轮转，避免生成器偏好某个答案位置。

另对每一道原题自动检查片段是否足以支持完整答案集合，即使基础题生成失败也执行。审核器盲于原题金答案，输出自己根据资料推得的索引和支持引文；程序随后才与金标签比较。该筛选称为“自动覆盖判断且与金标签一致子集”，不称为人工确认的充分证据，也不用于覆盖率的无偏估计。

## 解释规则

- 原闭卷错、加资料对：记为资料辅助改善；可能是知识补齐、调用改善或资料直接揭示答案，不能证明参数中完全没有知识。
- 原闭卷对、加资料错：记为资料干扰候选，对照组尤需检查。
- 在自动覆盖通过子集中，基础题闭卷和开卷都对、原题加资料仍错：仅列为需要复核的知识应用问题候选，不直接归为“推理缺失”。
- 资料未获自动验证、探针生成/审核失败、标签疑似问题、结果波动或输出解析问题分别保留，不能强制二分为缺知识/缺推理。
- 当前错题样本只适合分析失败机制；不能把其比例外推为模型总体知识或推理缺陷比例。自动生成和审核存在共享模型偏差，结论需附此限制。

诊断题及资料版本单独保存，均不用于训练；原测试集保持不变。后续训练数据不得直接采用这些题目的金答案、派生探针或题目特定资料包。本轮结果用于决定研究方向，不作为模型晋级成绩。
