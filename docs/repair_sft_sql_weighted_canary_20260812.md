# 一步 SQL 加权纠错 SFT 金丝雀（2026-08-12）

## 结论

完整门控流程已经跑完，候选不晋级，也不继续训练。

一步 `0.25/8/1` 加权确实让教师 SQL 更容易：SQL NLL 在 `16/16` 题上改善，均值从 `2.4484` 降到 `2.0612`（`-15.81%`）；329 个教师 SQL token 的 greedy 命中从 `166` 升到 `173`，top-5 命中从 `254` 升到 `261`，平均 rank 从 `56.59` 降到 `41.35`。但这没有转化为首条正确查询：新模型仍是 `0/16` 首条 SQL 支持 gold、`0/16` 与教师结果等价。

严格晋级门槛同时失败：逐题教师 SQL 几何平均概率超过 0.5 的数量仍为 `0/16`，门槛为至少 `12/16`；整段教师 SQL 全部 greedy 的题数也仍为 `0/16`。自由回放耗时约 `55m23s`，明显慢于 Step 120 的 `29m42s`，只有 `13/16` 条轨迹给出终止回答，缺失工具响应从 Step 120 的 `2` 增到 `9`。

因此不运行 held-out、不做完整老板评分、不扩到更多训练步。下一训练目标从“继续提高 SQL 权重”切换为“模型首个错误查询及其工具结果条件下的 SQL 恢复监督”。

## 训练与 checkpoint

- 来源：Step 120；同一 train236 16 题开发门禁，不是 held-out。
- 唯一变量：工具结构 `0.25×`、SQL payload `8×`、最终答案 `1×`；没有加入模型状态纠正样本。
- CPU mask 门禁：16/16 通过，SQL 占加权 loss mass 均值 `78.05%`。
- 一步训练退出码 `0`，墙钟约 `214s`；loss `2.250706`、grad norm `104.4080`、学习率 `1e-6`。
- 单卡峰值 allocated HBM `26.34 GiB`，整机 CPU 内存 `796.36 GiB`。
- 最终 checkpoint 含 32 个模型 distcp 主分片和 RNG extra；框架创建了空的 optimizer 占位目录，但其中无文件、大小为 0，内容清单只有 `model,extra`。

## 逐层门禁

| 门禁 | 结果 | 判定 |
| --- | --- | --- |
| 一步训练与 checkpoint | 退出码 0；模型分片完整；无 optimizer state | 通过 |
| SQL NLL | `2.4484 → 2.0612`，`16/16` 改善 | 通过 |
| SQL exact rank | greedy `166 → 173`；top-5 `254 → 261`；平均 rank `56.59 → 41.35` | 通过最低“rank 移动”条件 |
| 逐题 SQL 概率 | 超过 0.5：`0/16 → 0/16`，要求至少 `12/16` | 失败 |
| 首条 SQL 语义 | gold 支持 `0/16`；教师结果等价 `0/16` | 失败 |
| 自由回放停止/效率 | `55m23s`；终止回答 `13/16`；缺失工具响应 `9` | 退化 |

首条 SQL 分类从 Step 120 的 13 条错误/不足证据、3 条空结果，变为一步模型的 14 条错误/不足、2 条空结果。rank 改善因此只能解释为教师路径上的局部暴露提升，不能解释为自由策略已经越过首个语义分叉。

## 下一训练目标

下一轮不再单独提高 SQL loss 权重。应先离线构造“模型第一条错误 SQL → 实际工具结果 → 机械验证的纠正 SQL/答案”的短轨迹，让监督覆盖自由生成真正到达的状态；同时保留停止/重复查询护栏。该数据完成机械门禁后，再考虑新的单步金丝雀，仍从 Step 120 起跑并使用同一 rank、首条语义和终止行为门槛。
