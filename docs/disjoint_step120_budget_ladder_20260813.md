# Step 120 独立 64 题交互预算阶梯门禁

日期：2026-08-13

## 结论先行

强制完成 actor→rollout 权重同步后的 Step 120，在同一批与冻结 16 题、val20、test20 均不重叠的 64 题上，分别使用短、长和完整交互预算，最多只形成 `23` 个合格首错 SQL pair，低于预注册门槛 `48`。完整 25 次工具反馈运行形成 `22` 对，因此训练继续关闭，没有初始化 optimizer，也没有保存新 checkpoint。

增加交互预算确实让更多任务完成最终回答，并减少未观测工具调用，但没有把首错训练数据扩到可用规模。完整预算下仍有 `41/64` 题未发出可识别只读 SQL。现阶段不能靠降低门槛，或把环境探索命令、未执行 SQL 当作 rejected 来制造训练样本。

三次运行是相同 greedy 配置下的独立分布式执行，不把 `23 → 22` 解释为交互预算造成的逐题退化。可靠结论是：12 回合和完整 25 工具回合都远未达到 48 对，延长当前 64 题的预算已经没有足够的信息收益。

## 完整预算排除项

完整运行 `64/64` 行成功落盘，退出码为 0。首查构造器排除了 `41` 条无只读 SQL和 `1` 条首查正确或结果等价的轨迹；剩余 `22` 条均带有实际工具返回，其中 `19` 条为可执行但证据错误或不足，`2` 条为 schema/语法/执行错误，`1` 条返回空证据。

转换器观察到 `35` 条终止 assistant 回答、`51` 个未返回的工具调用以及 `8` 条终端截断工具调用。这些未观测调用没有进入 pair。安全聚合不包含原始 prompt、SQL、答案、任务 ID、工具输出或服务器路径。

## 归因边界与下一步

既有同状态 forward-only 证据表明原生模型与 Step 120 都是正确 semantic delta `0/16` 占优；同一 64 题的 3 回合对照又显示原生和 Step 120 都主要进行环境探索，Step 120 的早期 SQL 进度略高。因此缺陷在训练前已经存在，现有训练没有新制造或放大短预算探索模式。

但完整自然行为归因仍缺原生模型的同一 64 题完整 25 工具回合对照。下一步先补齐这一无训练对照；随后若仍需要 pairwise 训练，只能扩大经过额外语义复核、且继续与三份冻结集合隔离的 current-definition 任务池。`138` 条 review-required 任务不能仅凭 SQL 可执行和 gold 自洽自动放行。
