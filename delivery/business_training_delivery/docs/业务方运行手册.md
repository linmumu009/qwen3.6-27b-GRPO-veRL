# 业务方运行手册

文档版本：1.0；适用交付包：0.2.1；日期：2026-09-21。

本文说明如何在接收方服务器上准备环境、启动训练、查看结果及导出模型。所有命令均在 Linux 服务器终端执行。示例使用 `/data3/llin/business_training_delivery`，可以换成其他位置，但须保持包内目录结构完整。

## 1. 交付内容与使用范围

交付包包含原始 Qwen3.6-27B 模型、五类示例数据、训练入口、共享 veRL 框架及补丁、离线运行镜像和文档。`model/CPT` 为预留位置，尚未包含 CPT 成品模型；这不影响用原始模型运行 CPT 示例。

|训练类型|用途|数据目录|
|---|---|---|
|SFT|学习问答和指令样例|`datasets/SFT`|
|trajory-SFT|学习包含工具调用和最终回答的轨迹|`datasets/trajory-SFT`|
|GRPO|根据答案奖励训练|`datasets/GRPO`|
|agentic-GRPO|训练中实际调用计算器，再根据答案奖励训练|`datasets/agentic-GRPO`|
|CPT|基于原文继续进行语言模型训练|`datasets/CPT`|

`trajory-SFT` 沿用交付目录名称，输入命令时保持该拼写。每类含32条训练样例和8条验证样例，默认只训练1步，用于确认工程流程。

本包已在5号机完成五类单步训练，以及 SFT 检查点的 Hugging Face 格式导出核验。**尚未在接收方服务器验证，不代表正式训练效果已验收。** 两类 GRPO 简单样例曾出现奖励全为1、梯度为0，不能据此判断有训练收益。长时间训练、断点续训、导出模型的实际推理及业务效果不在已验证范围内。

此前验收生成的检查点、导出模型和临时日志已清理。包内保留验收摘要，需要模型产物时请重新运行。

## 2. 首次部署：由运维完成

### 2.1 准备服务器

相同硬件规格仍需核对驱动、设备映射和通信配置。已测试环境为 Ascend 910 A3，单机16个逻辑 NPU、每个64GB，主机约2TiB内存。这是参考配置，不是最低配置保证。

|项目|需要准备|
|---|---|
|系统与权限|Linux；账户能够使用 Docker 并访问 NPU，入口按 root 容器运行|
|容器服务|Docker 已安装并启动，账户可执行 `docker info`|
|驱动和固件|与设备及随包镜像兼容；`npu-smi info` 能正常识别设备|
|设备通信|单机设备通信正常，宿主机通信配置文件可用|
|磁盘|同时容纳完整归档、解包目录、Docker 导入的镜像及训练产物|
|设备占用|五类训练依次运行，真实训练前确保所需设备空闲|

镜像内包含 Python、PyTorch、CANN 等运行依赖，无需逐个在宿主机安装 Python 包。**宿主机驱动、固件和 Docker 仍由运维准备。** 镜像采用 CANN 9.0.0、torch 2.9.0 和 torch-npu 2.9.0.post2；更换镜像或升级依赖后需要重新验证。

原始模型约52GiB，镜像归档约16GB。每次单步检查点约55GB，模型导出还会额外占用约55GB。入口要求输出所在磁盘至少有90GB空闲；这个检查不包含 Docker 镜像导入所需空间，多次运行会累积产物。

运维先检查：

```bash
npu-smi info
docker info
df -h /data3
docker info --format '{{.DockerRootDir}}'
```

最后一条显示 Docker 存储目录，请同时检查该目录所在磁盘的剩余空间。

### 2.2 收包、校验和解压

交付方应提供完整的 `business_training_delivery.tar` 和对应 `.sha256` 文件。仅下载 Git 仓库中的脚本不够：模型、完整框架快照和离线镜像未全部存入 Git。

以下假设两个文件已放到 `/data3/llin`。先确认该位置没有同名旧交付目录；已有目录时应另选空目录解压，避免混合版本。

```bash
cd /data3/llin
sha256sum -c business_training_delivery.tar.sha256
```

校验显示 `OK` 后再执行：

```bash
tar -xf business_training_delivery.tar
cd business_training_delivery
```

校验失败则重新传输。解压后应看到 `model`、`datasets`、`Train`、`frameworks`、`environment`、`tools`、`outputs` 和 `docs` 等目录。

### 2.3 导入离线镜像

在交付根目录先校验镜像：

```bash
(cd environment && sha256sum -c ascend-verl-base.tar.sha256)
```

确认显示 `OK` 后导入：

```bash
docker load -i environment/ascend-verl-base.tar
docker image inspect --format '{{.Id}}' sha256:cdc98ccb6b739429aa81f3dc6e4bca9543d1e99202cd7e8686055fb5e9fae7b7
```

最后一条应返回对应镜像 ID。每台服务器首次部署时导入一次即可。启动脚本自动创建独立容器，结束后删除容器，结果保留在 `outputs` 中。业务人员无需手动创建或进入容器。运行默认使用本地模型和数据，关闭在线下载。

### 2.4 核对宿主机路径和设备

当前 `environment/run.sh` 挂载以下宿主机路径：

```text
/usr/local/Ascend/driver
/usr/local/Ascend/add-ons
/usr/local/dcmi
/usr/local/sbin
/etc/ascend_install.info
/etc/hccn.conf
```

映射的设备包括 `/dev/davinci[0-9]*`、`/dev/davinci_manager`、`/dev/devmm_svm` 和 `/dev/hisi_hdc`。目标服务器路径或设备布局不同时，由运维调整并重新验收。

当前空闲判断对应5号机的 `npu-smi` 输出：要求出现8条 `No running processes found`。设备实际空闲却仍提示占用时，应检查输出格式及设备布局，不能直接删除检查强行启动。入口已配置无限 memlock 和 `IPC_LOCK` 能力，无需添加特权容器参数。

## 3. 启动训练：业务人员操作

所有后续命令均在交付根目录执行：

```bash
cd /data3/llin/business_training_delivery
```

先运行预检：

```bash
bash Train/SFT/run.sh --check
```

预检检查模型、配置、数据格式、监督范围、奖励和计算器，并准备数据文件。**预检成功不等于真实训练成功。** 预检也会留下一个小型结果目录，它不包含训练检查点。其他训练类型可用同样方式追加 `--check`。

预检通过后，选择所需类型执行。下面每行是一项独立任务，依次运行，不要同时启动：

```bash
bash Train/SFT/run.sh
bash Train/trajory-SFT/run.sh
bash Train/GRPO/run.sh
bash Train/agentic-GRPO/run.sh
bash Train/CPT/run.sh
```

初始化需要加载27B模型及训练、生成引擎，单步运行也可能等待数分钟。保持终端连接，等待当前命令结束后再运行下一项，不要重复提交。

新服务器首次验收时，应依次完成五类单步训练，并按下一节确认结果。5号机历史记录不能替代新服务器的验收。

## 4. 查看结果和判断成功

结束时会显示结果目录及退出码，例如：

```text
结果目录：/data3/llin/business_training_delivery/outputs/SFT/运行编号；退出码：0
```

“运行编号”是每次自动生成的时间与进程编号，实际操作使用终端显示的真实目录。

|文件或目录|用途|
|---|---|
|`driver.log`|启动及运行日志，排错时优先提供|
|`exit_code`|退出码，成功应为0|
|`status.json`|真实训练成功应为 `"state": "completed"`|
|`preflight.json`|预检结果|
|`resolved_config.yaml`|本次配置|
|`checkpoints`|训练检查点|
|`tool_calls.jsonl`|agentic-GRPO 工具调用记录|

成功需同时确认退出码为0、状态为 `completed`、检查点已生成。入口检查分布式检查点基本结构；agentic-GRPO 还检查真实在线工具调用成功记录。预检成功不能代替这些条件。

结构完整不代表业务效果合格，仍需使用独立业务验证集评测。

## 5. 导出模型

默认产物为 Megatron 分布式检查点。需要 Hugging Face 格式时，在成功训练后执行导出。**下面的“运行编号”必须替换成真实训练目录名，不能原样执行。**

SFT 示例：

```bash
bash Train/SFT/run.sh --export-from outputs/SFT/运行编号/checkpoints/global_step_1
```

trajory-SFT、CPT 使用同样结构，替换对应训练类型即可。GRPO 和 agentic-GRPO 需要指向检查点下的 `actor`，例如：

```bash
bash Train/GRPO/run.sh --export-from outputs/GRPO/运行编号/checkpoints/global_step_1/actor
```

导出会生成新的结果目录，模型放在新目录的 `hf_export` 下。成功退出码为0，`status.json` 状态为 `exported`。导出同样需要可用设备和足够空间，请通过上述入口运行。

若训练时更换了基础模型，导出时也需通过相同的 `DELIVERY_MODEL_DIR` 指定对应模型。当前已验证 SFT 导出的张量名称、数量和形状，实际推理仍需另行验证。

## 6. 替换数据、模型和正式训练配置

### 6.1 替换数据

查看 `datasets/训练类型/README.md` 和 `example.jsonl`，按相同字段结构修改 `train.jsonl`、`val.jsonl`。训练集与验证集应互不重叠。入口自动生成 Parquet，日常修改 JSONL 即可。

替换后先运行对应入口的 `--check`，再进行1步真实训练验收。GRPO 当前奖励规则针对算术答案，agentic-GRPO 工具为受限计算器；换成业务任务时，需要同步适配奖励规则和工具，仅换题目文本不代表业务训练已经就绪。

### 6.2 使用 CPT 后的模型

将完整且兼容的 CPT 模型放入 `model/CPT`，包含配置、分词器、权重索引和全部权重分片。随后先预检：

```bash
DELIVERY_MODEL_DIR=model/CPT bash Train/SFT/run.sh --check
```

通过后再训练：

```bash
DELIVERY_MODEL_DIR=model/CPT bash Train/SFT/run.sh
```

当前该目录只是预留，直接使用会失败。替换模型后需要重新验收。

### 6.3 正式训练

由维护人员修改对应 `Train/训练类型/config.yaml`。当前默认1步、1轮，关闭断点恢复，仅保存模型及附加信息，没有保存优化器状态，不能直接承诺可断点续训。

正式训练需统一调整数据量、步数、轮次、保存频率、磁盘预算和运行超时。训练默认超时1800秒，可由维护人员通过配置顶层 `timeout_seconds` 调整；导出当前超时也为1800秒。不要仅增加步数就启动长任务。

入口不支持在命令末尾追加任意训练参数。并行配置针对16个逻辑 NPU 验证，改变设备数量或并行方式需重新适配。

## 7. 常见问题与报障

|现象|处理方式|
|---|---|
|找不到镜像|确认已导入离线镜像，固定镜像 ID 可查询|
|模型文件缺失|检查完整模型及权重分片是否传输齐全；CPT 预留目录不能直接使用|
|设备忙或任务持锁|等待任务结束；实际空闲仍报错时由运维检查设备布局和锁持有者|
|空间不足|检查输出所在磁盘，归档确认不再需要的结果后释放空间|
|驱动、设备或通信错误|由运维核对驱动、设备映射、通信配置及镜像兼容性|
|数据预检失败|根据数据目录说明修正字段、内容或长度，再次预检|
|长时间未完成或超时|查看日志和设备状态，由维护人员排查或调整超时，不重复启动|
|退出码非0或状态未完成|视为未通过，保留本次目录供排查|
|GRPO 奖励全为1、梯度为0|简单样例可能缺少组内差异，工程成功和有效学习须分别判断|

报障请提供训练类型、执行命令、完整结果目录路径、`driver.log`、存在时的 `status.json` 及 `npu-smi info` 输出，不要只截最后一行错误。

## 8. 交付方生成完整包

本节由交付方在5号机执行。打包前确保没有训练正在写入文件，且有足够归档空间。

```bash
cd /data3/llin/business_training_delivery
bash tools/package.sh /data3/llin/business_training_delivery.tar
```

归档必须放在交付目录之外；同名文件已存在时脚本会退出，应换一个新文件名。成功后将 `.tar` 和对应 `.tar.sha256` 一起交付；改名后接收步骤中的文件名也要相应替换。

打包包含模型、数据、框架、镜像和文档，排除运行产物及缓存。CPT 成品模型未放入时，其目录保持预留。接收方不需要重新导出源镜像或归档历史工程。
