# 客户训练操作手册

适用交付包：0.2.3。服务器环境由运维准备好后，客户按下面三步操作。

先进入交付目录（安装在其他位置时，替换这个路径）：

```bash
cd /data3/llin/business_training_delivery
```

## 第一步：放入新数据

选择训练类型，把新数据替换到对应目录下的 **train.jsonl** 和 **val.jsonl**：

|要做什么|数据放哪里|参数文件|
|---|---|---|
|问答、指令训练（SFT）|`datasets/SFT/`|`Train/SFT/config.yaml`|
|工具调用轨迹训练（trajory-SFT）|`datasets/trajory-SFT/`|`Train/trajory-SFT/config.yaml`|
|根据答案奖励训练（GRPO）|`datasets/GRPO/`|`Train/GRPO/config.yaml`|
|在线调用工具并按奖励训练（agentic-GRPO）|`datasets/agentic-GRPO/`|`Train/agentic-GRPO/config.yaml`|
|原文继续训练（CPT）|`datasets/CPT/`|`Train/CPT/config.yaml`|

- `train.jsonl` 放训练数据，`val.jsonl` 放少量不重复的验证数据；两个文件都需要有内容。
- 每行一条 JSON，格式参照同目录的 `example.jsonl`。无需修改数据路径或手动生成 Parquet。
- SFT 一行示例：`{"messages":[{"role":"user","content":"如何查询订单？"},{"role":"assistant","content":"在订单页面输入订单号查询。"}]}`
- CPT 一行示例：`{"text":"这里放需要模型学习的业务原文。"}`

当前配置限制单条 SFT/轨迹/CPT 数据不超过1024 token，GRPO 两类的输入不超过1024 token；超长数据需先拆分。SFT、GRPO 和 agentic-GRPO 每批4条，训练数据至少4条，建议条数为4的倍数；轨迹和CPT每批1条。

**GRPO 两类目前配套算术奖励和计算器。换成其他业务时，需先由技术人员适配奖励规则及工具；SFT 和 CPT 可按上述格式直接替换业务数据。**

## 第二步：修改训练参数

打开上表中对应的参数文件。文件内每行类似 `"trainer.total_epochs=1",`，只改等号后的值，保留引号和逗号。

首次检查新数据时，可以保持默认的1步。正式按数据轮次训练时，修改下面几项：

|找到这一项|改成什么|含义|
|---|---|---|
|`trainer.total_training_steps=1`|`trainer.total_training_steps=null`|取消只训练1步的限制，按轮次训练|
|`trainer.total_epochs=1`|先保持 `1`；训练3轮则改为 `3`|训练数据重复学习几轮|
|`trainer.save_freq=1`|`trainer.save_freq=100`|每100步保存一次，训练最后一步也保存|

另外，在配置文件最外层的第一行 `{` 后添加下面一行，保留末尾逗号；如果已经有这一项，直接修改数值，不要重复添加：

```json
  "timeout_seconds": 86400,
```

表示最多运行24小时，超过会停止；预计更长时增大秒数。其他参数先保持默认。学习率默认 `1e-6`；需要调整时，SFT/轨迹/CPT 同时修改 `optim.lr` 和 `optim.min_lr`，GRPO 两类修改 `actor_rollout_ref.actor.optim.lr`。

## 第三步：运行训练

选择对应的一行执行，一次运行一个任务：

|训练类型|启动命令|
|---|---|
|SFT|`bash Train/SFT/run.sh`|
|trajory-SFT|`bash Train/trajory-SFT/run.sh`|
|GRPO|`bash Train/GRPO/run.sh`|
|agentic-GRPO|`bash Train/agentic-GRPO/run.sh`|
|CPT|`bash Train/CPT/run.sh`|

以上默认使用原始模型。**使用我们提供的 CPT 后模型**时，在命令前加 `DELIVERY_MODEL_DIR=model/CPT`，例如：

```bash
DELIVERY_MODEL_DIR=model/CPT bash Train/SFT/run.sh
```

入口会先检查数据，再开始训练。只想检查、不训练，在同一命令末尾加 `--check`。

## 训练结果在哪里

结果保存在 `outputs/训练类型/本次运行编号/`。终端会打印实际路径；退出码为0、目录内 `status.json` 状态为 `completed` 表示完成，检查点在 `checkpoints/` 下。

失败时把本次目录中的 `driver.log` 发给维护人员。运行产物是训练检查点，需要导出为可加载模型时，由维护人员按[运维说明](运维部署与验收说明.md#5-导出模型)操作。
