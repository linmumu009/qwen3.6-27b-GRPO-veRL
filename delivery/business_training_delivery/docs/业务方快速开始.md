# 业务方快速开始

新服务器首次部署请先阅读[业务方运行手册](业务方运行手册.md)，完成校验、镜像导入和宿主机环境检查。

这份包演示五种训练方式的工程流程。运行前查看同目录的《验收状态》，未通过的项目不视为可交付能力。

## 5号机直接运行

先进入交付目录：

```bash
cd /data3/llin/business_training_delivery
```

按需要选择一条，依次执行：

|要做什么|命令|
|---|---|
|学习问答样例|`bash Train/SFT/run.sh`|
|学习包含工具调用的完整轨迹|`bash Train/trajory-SFT/run.sh`|
|根据答案奖励训练|`bash Train/GRPO/run.sh`|
|在线调用计算器并根据答案奖励训练|`bash Train/agentic-GRPO/run.sh`|
|继续学习原文|`bash Train/CPT/run.sh`|

默认只运行1步，适合确认流程。每次结果在 `outputs/训练类型/运行编号/`，正常结束时提示“退出码：0”。非零表示未完成，应将该目录的 `driver.log` 提供给维护人员。设备忙时入口会退出，等待已有任务结束后重试。

启动阶段需要加载27B模型和训练、生成引擎，通常要等待数分钟；1步训练也会包含这些启动时间。请等待当前命令返回，不要重复提交。

只检查数据和配置时，在命令末尾加 `--check`；这不代表实际训练成功。

## 替换数据和模型

替换对应 `datasets/训练类型/train.jsonl` 和 `val.jsonl`，每行一条记录，保持样例中的字段结构。验证集不应与训练集重复。修改后先运行该类型的 `--check`。

原始模型位于 `model/qwen3.6-27b`。CPT模型已放入 `model/CPT`，可用：

```bash
DELIVERY_MODEL_DIR=model/CPT bash Train/SFT/run.sh
```

## 拿到可加载的训练结果

训练检查点用于保存分布式训练权重。本次验收生成的检查点和导出模型已按要求清理。重新训练后，要导出Hugging Face格式，请将下面的“运行编号”替换为训练结束时显示的实际编号：

```bash
bash Train/SFT/run.sh --export-from outputs/SFT/运行编号/checkpoints/global_step_1
```

导出结果在新生成运行目录的 `hf_export/`。训练检查点和导出模型都很大，请按需保留。示例仅保存模型及元数据；需要恢复优化器状态的正式训练，应由维护人员调整保存配置。

## 搬到另一台机器

需要同类Ascend A3硬件、兼容驱动和Docker，不能直接用于普通CPU或NVIDIA机器。将完整目录复制过去，先加载随包镜像：

```bash
docker load -i environment/ascend-verl-base.tar
```

随后运行所需类型的 `--check` 和1步训练。异机运行尚未验收，环境要求详见 `environment/README.md`。

## 打包

在包根目录执行下面的命令，把输出路径替换成有足够空间的新路径。脚本包含模型、数据、代码及离线镜像，排除验收训练产生的大检查点和缓存。

```bash
bash tools/package.sh /data3/llin/business_training_delivery.tar
```

完整归档包含原始模型和CPT模型；本次仅补齐模型目录，最终归档需按上述命令另行生成。
