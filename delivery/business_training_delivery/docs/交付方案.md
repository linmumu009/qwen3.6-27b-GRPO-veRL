# 交付方案

## 操作界面
业务方只需在包根目录执行 `bash Train/训练类型/run.sh`。五类目录分别保留入口、配置和说明，共享一份veRL。默认1步工程验证；增加步数前先按硬件容量检查磁盘和训练参数。

## 五类内容
|类型|数据与目标|实现|
|---|---|---|
|SFT|单轮算术问答，仅监督回答|veRL SFT + Qwen完整模板assistant掩码|
|trajory-SFT|包含工具调用、返回和最终答案|相同SFT引擎，监督调用与答案|
|GRPO|算术问题与标准答案|veRL GRPO，在线采样4个回答、最终答案奖励|
|agentic-GRPO|要求调用计算器的算术任务|veRL Tool Agent Loop + 本地计算器 + 答案奖励|
|CPT|自编库存说明原文|veRL SFT引擎 + 原文CausalLM目标|

每类32条训练、8条独立验证。它们是自编的工程样例，并非官方GSM8K，也不代表业务训练效果。Agent训练与轨迹SFT分别是在线交互与离线监督，不能混为同一种训练。

## 环境与交付
适配Ascend A3单机16逻辑NPU；固定基础镜像ID，归档历史修改后的veRL与所需兼容模块。
所有训练使用新容器、新输出目录及本包路径，避免依赖历史实验检查点或业务沙箱。
CPT模型已放入model/CPT；训练入口仍默认从原始模型开始，可通过DELIVERY_MODEL_DIR=model/CPT切换。

## 验收标准
1. --check通过配置、数据、监督掩码或prompt长度、工具和奖励正负例检查。
2. 真正完成前向、反向、优化器步骤并保存可识别的检查点。
3. Agent额外记录真实rollout工具调用；预检工具调用不计入在线证据。
4. 对完成的检查点验证HF导出；跨机器迁移需在新位置加载离线镜像并复验。

逐项进展与限制记录在验收状态.md，不将预检成功写成训练通过。
